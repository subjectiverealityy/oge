Fronet 1

Fronet is an Internet Service Provider that serves university hostels and public spaces. They have partners called Financiers, that partly fund hostel deployments. I developed the frontend of their Financier web app. It displays real-time information to logged-in Financiers about network performance data, revenue data, anonymised internet usage data, and more.

I was given PDF reports of each hostel's performance data to translate into a web application. I created a low-fidelity Figma wireframe demonstrating a proposed content layout, and shared it with the founder. I used it as the foundation for a detailed design that I developed into a high-fidelity (frontend-only) React demo.

It was presented to prospective users for testing and feedback. I made iterations based on their feedback. After finalising the design and user flow, the backend developers started work on the database and backend. The next stage will be completing a Google Analytics integration and integrating endpoints that will bring in data from various third-party platforms.

Fronet 2

A captive portal is the webpage that is displayed when one tries to connect to a public Wi-Fi network. It usually requires a user action before granting internet access (in this case, it was inputting a voucher code). I customised a captive portal for Fronet. Their previous solution had limited customisation options.

Edits were originally made via their network platform's editor, but the platform gave the option of uploading the code for a custom captive portal. I downloaded the codebase template that was provided by the platform - it contained placeholder UI and code that already connected it to internet hardware. It was clear that updating some parts would disrupt the connection to internet hardware so I did research to determine the parts that should not be altered.

It was a legacy codebase written in HTML, CSS, JavaScript, and jQuery. I updated the UI to match what they had in their previous solution then used that as a base for making further customisations. I added a 30-second advertisement, external links to the company's website and a subscription plans, a terms of service checkbox and modal that users must agree to before they can submit their voucher code, and integrated Google Analytics. I tested it across different devices and browsers.

Ndara.ai 1

I worked at an AI startup for 13 months (in a 5-person frontend development team) where I translated Figma frames from the UI team into responsive web pages for a dashboard-style CRM application. We used mock data to build out the pages, pending when new endpoints and API documentation were sent by the backend team. On receiving new endpoints, we would fetch them via a shared RTK Query layer, and integrate them into the frontend.

We built the frontend codebase from scratch as founding members of the frontend team. I worked on web app routes for the landing page, onboarding screens, user sign-up/sign-in, the dashboard's layout components (sidebar and topbar), viewing the dashboard overview, viewing invoice history and downloading invoice PDFs, setting booking availability, viewing booking logs, editing profile information, and more.

Later on, I was assigned the task of testing the web app periodically, and would provide detailed reports on bugs that I found, along with suggested improvements. I was made a member of a new 2-person QA team after some time and was in charge of testing the mobile app on a regular basis (another frontend developer handled the testing of the web app). I prepared dated reports and followed up with the mobile team regarding issues that were flagged during testing.
